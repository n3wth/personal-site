You can use each skill when you need it. You do not have to follow the full sequence. In Claude Code and Antigravity, add the `/egm:` prefix. In Codex, select the skill from the skill picker.

| Skill | Use it to | Result |
| --- | --- | --- |
| `egm-brainstorm` | Test an idea | A concept brief |
| `egm-draft` | Turn a brief or existing notes into a design | A design document, written section by section |
| `egm-review` | Review a design with fresh agents across five stages | Findings for you to accept or decline |
| `egm-resolve` | Work through review findings | Agreed changes to the design |
| `egm-review-loop` | Run a configured group of reviewers for a specific task | Repeated review that stops on convergence |
| `egm-bootstrap` | Document an existing codebase | New or updated documentation |
| `egm-drift-report` | Compare checked-in documents with the code | A report of where they diverge |

## From idea to approved design

```text
/egm:egm-brainstorm Add offline reading to this app.
/egm:egm-draft
/egm:egm-review design_draft.md
/egm:egm-resolve
```

Brainstorming and review use fresh subagents. Each reviewer sees the document and its referenced source, without the conversation that produced them. You decide which findings to address before the design is approved.

## Start from an existing codebase

```text
/egm:egm-bootstrap
```

Bootstrap writes documentation grounded in the source, so later drafts and reviews have something accurate to read.

## After implementation

```text
/egm:egm-drift-report
```

The drift report compares the approved documents with the current code and lists where they no longer agree.

The [EGM repository](https://github.com/google/elephant-goldfish-model) has the full reference for each skill.
